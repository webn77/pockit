# 04. Project Naming & Positioning Research

본 프로젝트의 오픈소스 공개 및 브랜딩을 위해 적합한 명칭과 포지셔닝 전략을 리서치한 내용입니다.

## 1. 네이밍 성공 조건

1. **명확성(Clarity)**: 에이전트의 '보안/가드레일/결정론적 통제'라는 본질적 철학이 드러나야 합니다.
2. **간결성(Conciseness)**: 2음절 또는 2단어 조합으로, 발음하기 쉽고 GitHub URL로 치기 편해야 합니다.
3. **독창성(Originality)**: GitHub, PyPI 등에 동일 또는 매우 유사한 이름을 가진 경쟁 오픈소스가 없어야 합니다.
4. **글로벌 호환성**: 글로벌 AI Governance 트렌드(AI 규제, 통제된 자율성 등) 키워드와 자연스럽게 연결되어야 합니다.

## 2. 후보 이름 분석

### A. llm-agent-guardrail-engine
* **장점**: 직관적이고 검색 엔진 최적화(SEO)에 유리함.
* **단점**: 너무 길고(4단어), 고유한 브랜딩 가치가 떨어짐.

### B. safe-agent-starter
* **장점**: '안전함'과 '스타터킷'이라는 정체성이 잘 융합됨.
* **단점**: 다소 흔한 조합이며, '안전'의 기준이 모호하게 느껴짐.

### C. enterprise-llm-ops-kit
* **장점**: 엔터프라이즈 느낌을 강하게 줌.
* **단점**: LLMOps는 보통 인프라/배포/모니터링(Prometheus 등)을 의미하므로, 본 코드 중심 가드레일 프로젝트와 범위적 괴리가 있음.

### D. governed-agent (최종 선정)
* **장점**:
  * "LLM이 임의로 행동하지 않고 결정론적으로 통제(Governed)된다"는 프로젝트 정체성을 가장 정확히 표현함.
  * EU AI Act, AI Governance 등 전세계적인 AI 통제 흐름과 키워드가 일치함.
  * 2단어 13자로 타이핑 및 기억에 최적화됨.
  * GitHub 내에 해당 명칭을 메인 브랜드로 점유한 경쟁 레포가 없음.
* **풀 네임 브랜딩**: `governed-agent: Production-Ready LLM Agent Engine for High-Stakes Domains`
